Skriber began with a broad opportunity rather than a predefined feature set: reduce the documentation burden physicians face around patient consultations.

The problem wasn't transcription. It was attention.

Documentation competes with the thing physicians are actually there to do: understand and care for the patient in front of them. A transcript alone would still leave the physician with work to reconstruct the encounter.

Can we capture the important information from a clinical encounter and turn it into useful documentation without adding another complicated workflow?

Reduce uncertainty before writing requirements.

I investigated the transcription landscape across medical and general-purpose providers to understand:

  • Medical terminology: Clinical conversations contain specialized vocabulary
  • Real-time capability: The intended workflow depended on live consultation capture
  • API / SDK quality: Integration quality constrained the experience
  • Privacy / HIPAA: Clinical conversations contain sensitive patient information
  • Pricing: Variable AI and speech costs affect viability at scale

Why Deepgram

Deepgram won on: medical vocabulary accuracy (via custom model training), streaming latency under 300ms for real-time UX, BAA-ready HIPAA compliance, excellent SDK quality for rapid prototyping, and competitive per-minute pricing that supported pilot economics.

Azure and Google had compliance but worse real-time performance. Nuance had vocabulary but API limitations that would slow integration. IBM required complex setup that didn't match our timeline.

The product decisions

Key decision 01

Treat transcription infrastructure as a product decision.

Latency, healthcare vocabulary, integration, privacy and pricing all shaped what kind of experience we could offer. Deepgram became the transcription technology used in the working product.

Key decision 02

Build a workflow, not a transcript generator.

Skriber combined speech capture with AI-assisted summaries, sensitive-information handling, appointment/session management and historical access.

Key decision 03

Validate the core workflow before deeper integrations.

Native mobile and EMR integration were valuable directions, but first we needed to test whether capture → transcription → documentation created enough value.

Why this sequence

Web before mobile: Web-based capture could validate the core workflow faster without platform-specific development overhead. If the transcription + AI documentation didn't create value, mobile work would have been wasted effort.

EMR integration deferred: EMR integration depended on proving clinical value first. Without physician validation signals, integration work would be speculative feature development rather than proven product expansion.

Beta before scale: We needed real physician usage data to understand documentation quality, review patterns, and workflow friction before committing to native platform work or enterprise integrations.

Outcome

By May 2024, Skriber had progressed from technical research into a functioning AI healthcare product with a defined clinician-validation roadmap.

We turned an ambiguous AI opportunity into a working, pilot-ready healthcare product.

Later career materials indicate that the product subsequently grew to 5,000+ monthly users. I treat that as later product trajectory rather than a causal result of my tenure.

What I'd do differently

Looking back with more context:

Validate documentation format earlier

I'd validate the AI summary format and review UI with 3–5 physicians before building the full session-history architecture. We designed storage and retrieval patterns assuming a review workflow we hadn't actually tested with users.

Instrument earlier

Beta instrumentation should have been part of the MVP, not a "next" item. We shipped a working product but delayed the metrics that would tell us if it was creating value—transcription accuracy rates, time-to-review, edit frequency, and abandonment points.

Narrow the initial capture scope

We built appointment management (scheduling, patient association, metadata) alongside the core capture workflow. In retrospect, manual session start/stop would have been sufficient for pilot validation—the administrative layer could wait until we proved the clinical value.
